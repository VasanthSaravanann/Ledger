# `web/` — the Ledger workspace preview

A browser preview of the recruiter workspace: triage, dispositions, dispatch, governance
and audit, with 48 generated candidates and a session that ends when the tab does. It is
**not** the ledger — the Rust CLI at the repository root is what records a real
disposition, signs it and chains it.

Stack: TanStack Start + React 19 + Vite 8 + Tailwind 4, built with Nitro for Vercel.

```bash
bun install --frozen-lockfile
bun run dev        # http://localhost:5173
bun run lint       # eslint + prettier (ignores build output)
bun run test       # vitest
bun run build      # writes .vercel/output (Nitro preset: vercel)
```

`vercel.json` sets the install and build commands; the Vercel project uses this folder as
its Root Directory. `bun run build` alone is enough — Nitro's default preset is `vercel`,
and `NITRO_PRESET` overrides it if you want another target.

## Rules for this folder

- Keep the preview state in the shared React context (`ledger-context.tsx`) across routes.
  In-memory sample data is what keeps the preview from implying that Rust persistence,
  roles or signatures are connected.
- Never present a browser-side action as an Ed25519 signature, a signed approval or a
  verified append log. Production disposition, approval and audit work belongs to the
  Rust core.
- Style through the semantic tokens in `src/styles.css` (`--pass`, `--warn`, `--fail`,
  `--primary`, the 7px radius, the 70px top bar). The landing page and the workspace
  share them deliberately; see `../SKILL.md`, decision 24.
- `routeTree.gen.ts` is generated by the router plugin. Do not edit it.
