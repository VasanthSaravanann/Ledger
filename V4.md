# Ledger Hardening & Verifiable Correctness — Agent-Executable Task List

**Objective:** Eliminate live-pilot bricking failure modes, close injection/arithmetic/serialization bugs, and replace unverified test counts with enforceable invariants and independent verification.  
**Execution Order:** Strictly follow the 8-tier priority sequence below.

---

## Priority 1: Crash Safety, Concurrency & Recovery (§1)

- [ ] **Task 1.1: Atomic Append & Torn-Line Detection for Send Log**
  - **Action:** Refactor JSONL append operations to write a complete newline-terminated line, call `fsync()` on the file descriptor, and `fsync()` the parent directory.
  - **Guardrail:** On log load, explicitly detect any trailing partial/unterminated line and refuse silent repair.
- [ ] **Task 1.2: Atomic Write Protocol for Non-Log State Files**
  - **Action:** Route all non-log state writes (approvals, governance, QA records, dispositions) through `write to temp file -> fsync() -> atomic rename()` in the same directory.
- [ ] **Task 1.3: Advisory Directory Locking & Stale-Lock Recovery**
  - **Action:** Acquire an exclusive advisory lock (`fs2` / `flock`) on the `--data` directory for every mutating command.
  - **Lockfile Format:** Write `PID` + ISO-8601 UTC timestamp inside the lockfile. Document and implement a safe manual break procedure for stale locks after a process crash.
- [ ] **Task 1.4: Implement `ledger log quarantine` Recovery Command**
  - **Action:** Build `ledger log quarantine --reason <note>` to move an unverifiable/torn trailing tail to a timestamped `.quarantine` sidecar file alongside a signed-off operator note, restoring valid chain continuity without silent mutation.
- [ ] **Task 1.5: Interrupted-Dispatch Integration Test**
  - **Action:** Add a test that kills `ledger dispatch` after 70 of 147 valid sends, restarts it (with and without quarantine), and asserts **exactly 77 new sends** and **zero duplicate `APPLICATION_ID` dispatches**.

---

## Priority 2: Input Handling, Injection & Filesystem Security (§3)

- [ ] **Task 2.1: Single-Pass Template Renderer (Prevent Double-Expansion)**
  - **Action:** Replace multi-pass string replacement with a single-pass token scanner so candidate fields containing `{{...}}` (e.g., `FIRST_NAME = "{{ROLE_TITLE}}"`) render literally and never re-expand.
- [ ] **Task 2.2: Import-Time Header Injection & Email Validation**
  - **Action:** Reject any CSV row at import if `FIRST_NAME`, `EMAIL`, or any field rendered into email headers contains `\r`, `\n`, or ASCII control characters. Validate RFC-compliant email syntax at import rather than mid-dispatch.
- [ ] **Task 2.3: Strict HTML Escaping in `--export-html`**
  - **Action:** Escape all dynamic/candidate-derived values (`&`, `<`, `>`, `"`, `'`) during `--export-html` generation to prevent XSS and layout corruption.
- [ ] **Task 2.4: Hardened CSV Edge-Case Parser**
  - **Action:** Test and enforce deterministic handling of UTF-8 BOM, CRLF (`\r\n`), quoted commas, embedded newlines, duplicate `APPLICATION_ID`s, missing/extra columns, empty/0-row files, whitespace-only names, mononyms, non-Latin scripts, and zero-width / bidirectional Unicode characters.
- [ ] **Task 2.5: Path Traversal Defense & `0600` File Permissions**
  - **Action:** Canonicalize and confine `--data` and `--file` paths to prevent directory traversal, symlink escapes, and macOS case-insensitivity collisions. Enforce `0600` (`rw-------`) permissions on all created state and log files containing candidate PII.

---

## Priority 3: Boundaries, Checked Arithmetic & Sampling Stability (§4)

- [ ] **Task 3.1: Zero-Denominator & `NaN` Guards in Metrics**
  - **Action:** Handle `0` sends (reply volume per 1,000) and `0` attempts (form-block rate) explicitly without dividing by zero or producing `NaN`/`Inf`.
- [ ] **Task 3.2: Centralize & Test Inclusive/Exclusive Threshold Boundaries**
  - **Action:** Define all Green/Amber/Red band boundaries in a single module (`< 30` vs `== 30`, `== 80`, `== 10%`, `== 25%`) and write unit tests pinning every exact edge value.
- [ ] **Task 3.3: Enforce Checked Arithmetic on Counters**
  - **Action:** Add `#![deny(clippy::arithmetic_side_effects)]` across counter/metric modules and replace raw `+`/`-`/`*`/`/` with `.checked_add()`, `.checked_sub()`, etc.
- [ ] **Task 3.4: Stabilize & Document Deterministic 10% QA Sampling**
  - **Action:** Document the exact deterministic sampling hash/function (keyed strictly on `APPLICATION_ID` + `REQ_ID`) and add a regression test proving that adding unrelated CSV columns does not change which rows are selected for QA.

## Priority 4: Hash-Chain Canonicalization & Schema Compatibility (§2 & §6)

- [ ] **Task 4.1: Specify & Implement Canonical Byte Serialization for Hashing**
  - **Action:** Replace raw `serde_json` hashing with a documented canonical byte serializer: lexicographically sorted keys, explicit Unicode NFC normalization, zero floating-point fields, and an explicit field-coverage allowlist.
- [ ] **Task 4.2: Explicit Genesis Entry & Monotonic Timestamp Verification**
  - **Action:** Define and validate an explicit `GENESIS` entry in `ledger log verify`. Enforce monotonic (non-decreasing) timestamps across sequential chain entries.
- [ ] **Task 4.3: Hash-Chain Mutation & Schema Evolution Tests**
  - **Action:** Add tests proving:
    1. Reordering JSON keys in a persisted log entry fails verification if canonicalization is bypassed or alters raw bytes as expected.
    2. Adding a new optional field in a future release still verifies existing entries without breaking old digests.
- [ ] **Task 4.4: `schema_version`, Golden Fixtures & Migration Command**
  - **Action:** Stamp `schema_version` on every persisted record and fail closed on unknown versions. Commit golden log/state fixtures from the current release to CI so future builds fail if a `serde` rename breaks backward compatibility. Add a documented `ledger migrate` command that never rewrites chained logs in place.
- [ ] **Task 4.5: Declare & Test MSRV in CI**
  - **Action:** Pin `rust-version` in `Cargo.toml` and add a CI matrix leg testing against that exact Minimum Supported Rust Version.

## Priority 5: Evidence-Grade Test & Verification Suite (§5)

- [ ] **Task 5.1: Enforce Code Coverage Floor (`cargo-llvm-cov`)**
  - **Action:** Configure `cargo-llvm-cov` in CI with a hard minimum coverage threshold (e.g., `>= 85%` line/branch coverage on core modules).
- [ ] **Task 5.2: Run Mutation Testing (`cargo-mutants`)**
  - **Action:** Configure `cargo-mutants` to verify that test assertions actually catch logic inversions, off-by-one boundary changes, and skipped validation checks.
- [ ] **Task 5.3: Property-Based Invariant Testing (`proptest`)**
  - **Action:** Write `proptest` suites proving:
    - A blocked row never renders an email.
    - `SUPERSEDES` chains always resolve to exactly one live record with zero cycles.
    - `ledger log verify` passes if and only if the log bytes are unmutated.
- [ ] **Task 5.4: Fuzz Harnesses (`cargo-fuzz`)**
  - **Action:** Add `cargo-fuzz` targets for the CSV importer and JSONL log parser.
- [ ] **Task 5.5: Snapshot Tests (`insta`), Type-State Compile Tests (`trybuild`), & Unsafe Ban**
  - **Action:** Add `#![forbid(unsafe_code)]` at crate root. Create `insta` snapshots for every `Template × Gate × Version` combination, plus `trybuild` compile-fail tests proving invalid state transitions cannot compile.

## Priority 6: Strict Lints, CLI Contract & Operator Audit Log (§7)

- [ ] **Task 6.1: Ban Panicking Operations in Production Code**
  - **Action:** Enforce `#![deny(clippy::unwrap_used, clippy::expect_used, clippy::panic, clippy::indexing_slicing)]` across all non-test crate modules.
- [ ] **Task 6.2: Documented Exit Codes & `--json` Output on All Commands**
  - **Action:** Assign stable, documented exit codes distinguishing success (`0`), circuit-breaker block (`2`), invalid input/schema (`3`), lock contention (`4`), and internal error (`1`). Add `--json` structured output to every subcommand.
- [ ] **Task 6.3: PII-Safe Error Handling & Mutating Confirmation Flags**
  - **Action:** Disable default backtraces (`RUST_BACKTRACE=0`) and scrub candidate PII from all error/panic messages. Require interactive confirmation or `--yes` on all mutating commands.
- [ ] **Task 6.4: Operator Action Log, Shell Completions & Man Page**
  - **Action:** Write a separate append-only `operator.jsonl` audit log recording operator identity, command, flags, and timestamp distinct from the candidate send log. Generate shell completions and a man page at build time.

## Priority 7: Supply Chain, Multi-Platform Packaging & Timezone Correctness (§8 & §9)

- [ ] **Task 7.1: Supply-Chain Audits & Zero-Network Proof in CI**
  - **Action:** Commit `Cargo.lock` with pinned dependencies; run `cargo-deny` and `cargo-audit` in CI. Add a CI assertion checking `cargo tree` for zero networking crates and executing tests inside a network-isolated sandbox (`unshare -n`).
- [ ] **Task 7.2: Reproducible Cross-Platform Release Artifacts**
  - **Action:** Configure CI release builds with SHA-256 checksums and signed Git tags targeting macOS (`aarch64`, `x86_64`), Linux (`glibc`, `musl`), and Windows (`x86_64` — validating Windows path separators and CRLF behavior).
- [ ] **Task 7.3: CI HTML Drift Check**
  - **Action:** Add a CI check that runs `ledger dispatch --preview --export-html` and diffs against committed site HTML, failing the build on any drift.
- [ ] **Task 7.4: Timezone (`Australia/Melbourne`) & Business-Hour SLA Tests**
  - **Action:** Store all timestamps in UTC with explicit offsets, render display times in `Australia/Melbourne`, and add unit tests across an AEST/AEDT daylight saving transition proving business-hour SLA calculations remain accurate.
- [ ] **Task 7.5: Backup & Restore Verification Test**
  - **Action:** Add an end-to-end test archiving `--data`, restoring to a fresh path, and asserting `ledger log verify` passes cleanly.

## Priority 8: Independent Verifiability & Threat Model (§10)

- [ ] **Task 8.1: Ship Standalone External Log Verifier (`verify_log.py`)**
  - **Action:** Write and ship a self-contained ~30-line Python standard-library script (zero third-party dependencies, zero reliance on the `ledger` binary) that independently parses `send_log.jsonl`, recomputes canonical digests, checks monotonic timestamps, and verifies the hash chain.
- [ ] **Task 8.2: Publish Data Format Specification & Threat Model**
  - **Action:** Commit `FORMAT_SPEC.md` (field-by-field schema, canonical byte encoding, and digest coverage rules) and `THREAT_MODEL.md` (explicitly stating that the hash chain detects post-hoc edits and truncation, while full directory write access allows wholesale rewriting unless logs are replicated off-host).
