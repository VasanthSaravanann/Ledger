## Phase 1: Unblock CI, Security Permissions & Packaging (Immediate)

*Goal: Get CI 100% green, secure local PII files, and publish a clean open-source release.*

* [ ] **Fix MSRV 1.85 compilation (`src/pipeline.rs:194`)**
* Refactor the unstable Rust 2024 `let`-chain into nested `if let` / `match` statements so `cargo check --locked` passes on Rust `1.85.0`.


* [ ] **Enforce `0600` / `0700` file permissions on PII storage**
* Update `Store::save` and `Store::append` (using `std::os::unix::fs::PermissionsExt`) to create workspace directories with `0700` and write `dispositions.jsonl`, `operator.jsonl`, and imported ATS CSVs with `0600`.
* Add an integration test asserting `mode & 0o777 == 0o600` on newly created PII files regardless of OS `umask`.


* [ ] **Resolve `cargo-deny` unmaintained `chrono` advisory**
* Either migrate timestamp handling from `chrono` to `jiff` (recommended for clean supply-chain audits) or add a documented ignore entry with expiry and rationale in `deny.toml`.


* [ ] **Reconcile unit test coverage floors**
* Add targeted unit tests for error/edge paths in `src/pipeline.rs` (currently 69%), `src/metrics.rs` (80%), and `src/template.rs` (61%), or update `tarpaulin`/`llvm-cov` floor thresholds in CI with documented rationale in `CONTRIBUTING.md`.


* [ ] **Scrub PII from `stderr` & disable backtraces by default**
* Force `std::env::set_var("RUST_BACKTRACE", "0")` at the start of `main()` unless explicitly overridden in debug builds.
* Replace raw applicant IDs, names, and emails in `thiserror`/`anyhow` error strings with redacted/hashed identifiers (`app_hash[0..8]`).
* Require `--yes` flag on all destructive/mutating batch commands (`quarantine`, `purge`, `migrate`).


* [ ] **Add `LICENSE` & Release Pipeline**
* Add standard `MIT` `LICENSE` file matching `Cargo.toml`.
* Configure `cargo-dist` (or GitHub Actions release matrix) to build signed Linux/macOS binaries with SHA-256 checksums on version tags.

## Phase 2: Complete Audit Trail, Privacy Retention & CLI Hardening

*Goal: Enforce Australian Privacy Principles (APP) retention rules and eliminate single-operator trust gaps.*

* [ ] **Log every mutating command to `operator.jsonl**`
* Extract a shared `OperatorAudit::record(action, target_hash, metadata)` hook and wire it into `init`, `import`, `dispose`, `export`, `render`, `quarantine`, `purge`, and `migrate` (currently only `quarantine` logs).


* [ ] **Implement `ledger purge` for APP retention enforcement**
* Read `policy.retention_days` from workspace config.
* Identify records in `dispositions.jsonl` and ATS CSVs past expiry; replace PII fields (`name`, `email`, free-text notes) with `[PURGED:<sha256_prefix>]` tombstones while preserving record hashes and sequence links so `verify_log.py` still validates chain integrity.
* Write a `PURGE` summary event into `operator.jsonl`.


* [ ] **Implement `ledger migrate` for schema evolution**
* Add `schema_version` detection on workspace load and implement `ledger migrate` (per `FORMAT_SPEC.md §10`) with automatic pre-migration snapshot backup.


* [ ] **Expand `--json` output across all 19 CLI subcommands**
* Standardize a `{ "ok": bool, "data": ..., "warnings": [...] }` envelope across the remaining 13 subcommands so external scripts and the web UI can consume them deterministically.


* [ ] **Add off-host chain-head anchoring (`ledger anchor`)**
* Implement a post-dispatch hook/command that outputs a signed chain-head receipt (timestamp, record count, Merkle/chain head SHA-256) and supports pushing via configurable webhook URL or local append-only Git commit.

## Phase 3: Multi-User Authentication & Role-Based Access Control (RBAC)

*Goal: Replace spoofable `$USER` strings with verifiable operator identities and separation of duties.*

* [ ] **Replace `$USER` with signed operator sessions / keypairs**
* Add `ledger operator register --name <name> --role <coordinator|approver|auditor>` generating an Ed25519 keypair (stored in OS keychain or `0600` keyfile).
* Sign every disposition and sign-off entry in `dispositions.jsonl` and `operator.jsonl` with the active operator's Ed25519 signature; update `verify_log.py` to verify operator signatures alongside hash links.


* [ ] **Enforce Role-Based Access Control (RBAC)**
* **`coordinator` / `recruiter`:** Permitted to run `import`, `dispose`, `render`, `export`.
* **`approver` (Hiring Manager / Legal):** Permitted to cryptographically sign off on gate libraries, email templates, and retention policies (converting the 0/13 checklist into verified sign-off records).
* **`auditor`:** Restricted to read-only `verify`, `metrics`, and `audit` views.


* [ ] **Automated pre-mutation backups & tamper drift check**
* Automatically snapshot `dispositions.jsonl` and config to `.ledger/backups/<timestamp>/` before batch mutations.
* Block `dispose` and `render` if the SHA-256 of the gate library or email template no longer matches the `approver` sign-off hash.

## Phase 4: Recruiter Web UI (`ledger ui`) & Email Dispatch Bridge

*Goal: Make Ledger usable by non-technical recruiters and coordinators without touching CLI flags.*

* [ ] **Scaffold local `axum` web server (`ledger ui --port 8420`)**
* Bind strictly to `127.0.0.1` with a one-time session token printed on launch (opening browser automatically).
* Reuse the existing Rust core (`pipeline`, `template`, `store`, `metrics`) directly—no duplicate business logic.


* [ ] **Build Recruiter Triage Queue View**
* Display imported ATS applicants in a filterable table (`Pending`, `GATE Rejected`, `FIELD Rejected`, `Shortlisted`).
* Side-drawer candidate view showing parsed ATS columns, mandatory gate checklist, `GATE` / `FIELD` code selector, and live rendered email preview.


* [ ] **Build Bulk Disposition Flow**
* Allow multi-selecting applicants failing the same mandatory criterion (e.g., `GATE-01: Work Rights`), displaying a summary confirmation modal with exact count and template preview, and committing all dispositions atomically to `dispositions.jsonl`.


* [ ] **Add Guided ATS CSV Column Mapper**
* On CSV upload in `ledger ui` (or `ledger import --interactive`), detect header mismatches (Workday, Greenhouse, PageUp, SmartRecruiters exports) and save a reusable mapping profile in workspace config.


* [ ] **Build One-Click `.eml` Batch Export & Dispatch Tracker**
* Generate RFC 5322 `.eml` draft files bundled as a `.zip` (with `To`, `Subject`, `X-Ledger-Disposition-ID`, and rendered body) so coordinators can open/send directly in Outlook or Apple Mail without copy-pasting.
* Add a "Mark Batch Dispatched" button that records dispatch timestamps and triggers the off-host chain-head anchor.


* [ ] **In-UI Sign-Off Checklist (0/13 → 13/13)**
* Render the 13 operational/legal readiness items in the UI with role-gated "Sign Off" buttons for `approver` keys, blocking live mode until all 13 are signed.
