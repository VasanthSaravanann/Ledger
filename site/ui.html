Recruiter workspace

A local, loopback-only web workspace over the same core: ledger ui --operator <name> --port 8420 serves 127.0.0.1 and nothing else. It is behind the optional ui feature, so the default build stays the offline CLI.

cargo build --release --features ui
ledger --data pilot --operator rec-rui ui --port 8420
# http://127.0.0.1:8420/?token=<32-byte hex>

How it stays safe

  • One operator per process. The session is bound at launch from --operator; identity is a name plus a 0600 keyfile, not an account, so switching operators is a relaunch.
  • Token, then cookie. The first GET /?token= consumes a one-time token and sets HttpOnly; SameSite=Strict ledger_session, then redirects. Everything else needs the cookie (401).
  • RBAC per request. Mutations consult Role::permits; an auditor gets 403 on /api/dispose* and 200 on /audit.
  • The workspace lock is the boundary. Writes take Store::lock (flock) inside spawn_blocking; contention is 409 with the holder. Reads never block on a CLI run.
  • No assets on the wire. CSS and JS are embedded with include_str!, system fonts only, no CDN, no build step — it works air-gapped.
  • Bulk capture is one write. A batch is validated against the log plus the batch already staged, then lands in a single append_batch; a rejected batch writes zero bytes.
